# 오늘 뭐 먹지 — 설계 문서

작성일: 2026-11-02

## 1. 목적과 배경

- **문제**: 배달앱 등에서 메뉴를 고르는 게 귀찮다.
- **목적**: 본인이 매일 실제로 쓰는 도구. 나중에 출시·수익화 가능성도 열어둔다.
- **먹는 방식**: 그때그때 다름 (배달 / 외식 / 집밥).
- 여러 앱 만들기 계획의 첫 번째 앱. 두 번째는 "남자 화장품 가이드" (별도 설계).

## 2. 성공 기준

- 앱을 열고 **10초 안에** 메뉴 하나가 정해진다.
- 최근 **3일** 안에 고른 메뉴는 추천되지 않는다.

## 3. 범위

**포함**
- 질문 3개 → 조건에 맞고 최근에 먹지 않은 메뉴 1개 추천
- 고른 메뉴 기록, 기록 보기·삭제
- 먹는 방식별 외부 링크 연결
- PWA: 폰 홈 화면 설치, 오프라인 실행

**제외 (지금은 안 함)**
- 로그인, 서버, 기기 간 동기화
- 가게 정보·가격·리뷰 직접 조회
- 메뉴 직접 추가 기능, 취향 학습
- 광고·제휴 등 수익화 기능

## 4. 기술 선택

- 빌드 도구 없는 **순수 HTML/CSS/JS PWA**.
- 저장소: 브라우저 `localStorage`. 브라우저 데이터를 지우면 기록도 사라진다 (허용).
- 배포: GitHub Pages (무료).
- 나중에 규모가 커지면 React+Vite 또는 서버 구조로 옮긴다. 지금 대비하지 않는다.

## 5. 화면 흐름

### 5.1 질문 화면
한 화면에 질문 3개, 모두 탭으로 선택한다.

| 질문 | 선택지 |
|---|---|
| 어떻게 먹어요? | 배달 / 외식 / 집밥 |
| 어떤 게 당겨요? | 든든 / 가벼운 / 얼큰 / 상관없음 |
| 누구랑? | 혼자 / 여럿 |

- 지난번에 고른 답이 미리 선택돼 있다 (`localStorage`에 저장). 처음엔 첫 번째 선택지와 "상관없음".
- **[골라줘]** 버튼 → 결과 화면.

### 5.2 결과 화면
- 추천 메뉴 1개를 이모지와 이름으로 크게 표시한다.
- **[이걸로!]**: 기록에 저장 → 먹는 방식에 맞는 동작(6.3) 실행.
- **[다른 거]**: 같은 조건으로 다시 추천한다. 이번 세션에서 이미 보여준 메뉴는 제외한다.
- **[← 다시 고르기]**: 질문 화면으로 돌아간다.

### 5.3 기록 화면
- 최근 기록을 최신순으로 보여준다 (메뉴, 날짜).
- 항목별 삭제 버튼이 있다.
- 질문 화면에서 링크로 이동한다.

## 6. 데이터와 로직

### 6.1 메뉴 데이터 (`menus.js`)
```js
{ name: "김치찌개", emoji: "🍲",
  ways:   ["배달", "외식", "집밥"],
  tastes: ["든든", "얼큰"],
  group:  ["혼자", "여럿"] }
```
- 한식·중식·일식·분식·양식 등 50~80개로 시작한다.
- 모든 메뉴는 `ways`, `tastes`, `group`에 값이 최소 1개씩 있다.

### 6.2 추천 로직 (`app.js`, 순수 함수)
`pick(menus, answers, history, shownThisSession, now)` → 메뉴 1개 또는 `null`

1. **조건 거르기**: `ways`에 답이 포함되고, `tastes`에 답이 포함되며("상관없음"이면 이 조건은 건너뜀), `group`에 답이 포함된 메뉴만 남긴다.
2. 그중 `shownThisSession`에 있는 메뉴를 뺀다.
3. **최근 3일 제외**: `now - 기록 시각 < 72시간`인 기록의 메뉴를 뺀다.
4. 남은 후보가 있으면 그중 무작위로 1개를 고른다.
5. 3단계 이후 후보가 없으면, 2단계 결과에서 **마지막으로 먹은 시각이 가장 오래된** 메뉴를 고른다 (먹은 적 없는 메뉴가 가장 우선).
6. 2단계 결과가 비어 있으면(조건에 맞는 메뉴를 이번 세션에 다 봤음) `shownThisSession`을 비우고 1단계부터 다시 한다. 1단계 결과가 비어 있으면 `null`을 반환한다 → "조건에 맞는 메뉴가 없어요" 문구와 함께 [다시 고르기]를 보여준다.

### 6.3 [이걸로!] 동작
| 방식 | 동작 |
|---|---|
| 배달 | 메뉴 이름을 클립보드에 복사하고 "복사됐어요, 배달앱에서 붙여넣기 하세요" 안내를 띄운다. 배달앱 자동 실행은 하지 않는다 (웹에서 불안정). |
| 외식 | `https://map.naver.com/p/search/근처%20{메뉴}` 새 탭 |
| 집밥 | `https://www.youtube.com/results?search_query={메뉴}%20레시피` 새 탭 |

클립보드 복사에 실패하면 메뉴 이름을 선택 가능한 텍스트로 보여준다.

### 6.4 저장 (`localStorage`)
- `history`: `[{ name, at }]` (`at`은 ms 타임스탬프). 최근 100개만 유지한다.
- `lastAnswers`: `{ way, taste, group }`
- JSON 파싱에 실패하면 빈 값으로 시작한다 (앱이 멈추지 않게).

## 7. 파일 구조
```
index.html      화면 3개 (섹션 전환)
style.css       모바일 우선 스타일
app.js          추천 로직(순수 함수) + 화면 + 저장
menus.js        메뉴 데이터
manifest.json   PWA 이름·아이콘
sw.js           오프라인 캐시
icon.png        홈 화면 아이콘
test.html       추천 로직 테스트 (브라우저에서 열면 결과 표시)
```

## 8. 테스트
`test.html`에서 `pick`을 검사한다.
- 조건 필터: 배달·얼큰·혼자일 때 태그가 맞는 메뉴만 나온다.
- "상관없음"이면 맛 조건을 무시한다.
- 3일 안에 먹은 메뉴는 나오지 않고, 3일이 지난 메뉴는 다시 나온다.
- 후보가 모두 최근 기록이면 가장 오래전에 먹은 메뉴가 나온다.
- [다른 거]를 반복하면 이미 본 메뉴는 다시 나오지 않고, 다 보면 순환한다.
- 조건에 맞는 메뉴가 없으면 `null`.
- 깨진 `localStorage` 값으로 시작해도 앱이 동작한다.

화면은 폰 크기(375px)로 직접 눌러 확인한다.

## 9. 배포
1. 로컬에서 `index.html`을 열어 확인한다. 서비스워커는 `localhost`에서 확인한다.
2. GitHub 저장소에 올리고 GitHub Pages를 켠다.
3. 폰 브라우저에서 접속한 뒤 "홈 화면에 추가"를 한다.
